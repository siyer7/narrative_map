* Consider the inputs stage of the recipe (meta/pipeline1.md): contrast bayesian surprisal against a per-narr reading of the same input, to see what a single global signal cannot say. Consider an input where each timestep is a 15-dim embedding made of 3 narrs: narr1 captured by features 1-5, narr2 by features 6-10, narr3 by features 11-15. Say the input is 100 timesteps long.
* Say that which narrs are on follows a markov chain over the sets of narrs that can be on together, one step per timestep. A set always holds at least one narr, so the story never goes silent, and any narr may join a set that is already running. Each narr carries its own tendency to persist: p(stay on), p(stay off) = .95, .8 for narr1 and .93, .93 for narr2 and narr3, so narr1 holds the floor most of the time and all switch rarely. A run has to last at least 4 timesteps before that narr may switch, so the story does not flicker. narr1 starts on. The script prints each narr's on and off times, and asserts that no timestep is silent.
* Say seed 3 gives narr1 4 switches, narr2 5 and narr3 4, with narr1 on for 90 timesteps, narr2 for 36 and narr3 for 37; the number of narrs on at a timestep is 1 for 38 timesteps and 2 for 61, and 3 for only 1.
* Say that a narr's 5 features carry one shared mean feature value (1) while it is on and 0 while it is off, with no noise either way (narr_on_feat_noise and narr_off_feat_noise are both 0). So the input is exactly binary and every narr reads at the same brightness in the input matrix.
* Say that narr1 is green, narr2 purple and narr3 orange wherever they appear: their rows in the input matrix and their lines and ticks in every per-narr panel. Bayesian surprisal, being one signal for the whole input, is blue.
* Say that bayesian surprisal is read off the input, not off which narrs are on. prob_narr_resumed(t) = sum over a narr's 5 features of max(input(t) - input(t-1), 0), how much its features increased since the previous timestep; bayesian_surprisal(t) sums that over the narrs. It is exactly 5.00 at every event start and 0.00 everywhere else, and fires 7 times. It says an event started, and cannot say which narr started it.
* Say we read each narr off the input by how much the input *looks like* that narr. Give each narr a template: the mean feature value on its own 5 features, 0 on the other 10. The narrative match is cos(narr_template, input(t)), which is a level, not a change, so it holds high all through that narr's events and sits at 0 in its gaps.
* Say the cosine takes only 4 values here, and which one it takes depends on how many *other* narrs are on. A narr alone reads 1.00, sharing with one other 1/sqrt(2) = 0.71, sharing with both 1/sqrt(3) = 0.58, and 0.00 while off. The narr itself is doing exactly the same thing in the first three.
* Say this is because the cosine divides by the norm of all 15 features, so the other narrs sit in its denominator. The projection, input(t) dotted with the template's unit direction, does not normalize by feature length, and reads 2.24 = sqrt(5) whenever the narr is on regardless of who else is. narrative_continuity = cos x the input's norm, which the script asserts, so they are the same reading with and without that division.
* Say the same thing in 2d, where it can be read by hand: let the two features be [narr1, narr2], so narr1's direction is [1, 0]. With both narrs on the input is [1, 1], whose length is pythagoras, sqrt(2). The projection is 1 either way, since the direction is 0 on narr2's feature and that term drops out of the dot product; the cosine falls from 1 to 1/sqrt(2) = .71, because narr2's feature is in its denominator. The script asserts all four numbers.
* Say memory commits(t) = the narrative match above .5, one raster row per narr. It recovers exactly the timesteps each narr is on -- 90, 36 and 37 -- read off the input alone, which the script asserts. At .5 the cosine and the projection pick out the same timesteps, since on is 1.00 or 0.58 against off at 0.00.
* Say sparse memory nodes(t) = the narrative match changing at all, abs(diff of the cosine) > 0, one raster row per narr. This is where reading the match as a cosine costs us: a narr's cosine moves whenever *any* narr switches, so a switch spikes every narr it touches rather than the one that switched.
* Say the cost is visible in the counts. There are 13 actual switches across the three narrs, but 26 spikes: narr1 12, narr2 8, narr3 6. No narr ever spikes alone -- 10 timesteps have two narrs spiking and 2 have all three. Half the raster is narrs reacting to somebody else's switch.
* Say the combos a spike can take are num_compositional_narrs = 2**n_narrs - 1 - n_narrs, which is 4 here. Of the 2**n_narrs subsets of the narrs, the empty one is not a spike pattern at all (it is the timesteps where nothing switched) and the n_narrs singletons cannot occur, leaving the subsets of size 2 or more. The script asserts that no more than that many distinct combos appear. It grows like 2**n_narrs while the switches it has to encode grow like n_narrs: 1 combo for 2 narrs, 4 for 3, 11 for 4, 26 for 5.

## Notes

* bayesian surprisal fires 7 times, all of them event starts, and cannot attribute any of them. The per-narr rasters attribute every tick by colour, which is the whole reason for reading the input per narr rather than as one signal.
* the cosine's levels crowd together as narrs are added: 1.00, 0.71, 0.58 for one, two, three narrs on. With more narrs the spurious steps shrink toward the real ones, so the artifact gets harder to threshold away rather than easier.
* with the input binary and no feature noise, every metric is exact rather than approximate, so the figure shows the structure of the metrics and none of their variance. Noise is what would separate them on robustness, and that is not tested here.
